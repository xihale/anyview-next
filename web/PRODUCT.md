# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

广东工业大学在校生。日常自习与考前刷题：长时间坐在桌前，键鼠为主，同时看题面和写 C 代码。同一产品也用于考试时段。

## Product Purpose

把 AnyView OJ 的刷题闭环（题库 → 题面 → 编辑器 → 编译运行 / gdb 单步 → 评测）从官方网页搬进本地客户端。成功 = 打开题目后能立刻读题、写码、看到真实编译/运行结果，不被界面抢走注意力。

## Positioning

本地 Go relay 收敛会话与协议（RSA 登录、XFF 绑定、exam WS、gdb-service），前端用真实 gcc 诊断当编辑器 lint、用原版 gdb 载荷做单步调试。邻校通用 OJ 网页或 VS Code 插件做不到这条官方协议闭环。

## Operating Context

- 桌面浏览器里的 Nuxt SPA，relay 在本机 `:8787`
- 工作流：按章找题 → 读题面（含代码块/结构体）→ 写码 → Ctrl+Enter 运行 → 读输出/诊断；中频进入 gdb（断点、变量树、调用栈）
- 键盘：F8–F11 / Ctrl+Enter / Ctrl+B / `/` 已存在，不得破坏
- 窄屏：题面 / 代码 / 输出三 tab
- 深浅双主题都要能用（考场光照不定）
- mock 模式可离线演示，不碰真实上游

## Capabilities and Constraints

保留：登录、方案/班级切换、题库、题面、草稿、云端保存、编译运行、gcc 诊断、gdb 调试、设置。

**计时不上屏。** 用户确认：不把「挂够时长才能交」做成产品功能；写多久就是多久。顶栏计时条、时钟、挂机叙事全部删除。relay 在开题时仍静默 tick exam WS（上游 accumTime 协议，否则平台时长为 0）——这是兼容，不是功能，界面不展示、不引导。

**Zen：** 默认完整工作台；设置或快捷键进入 Zen（侧栏 / 顶栏 / 输出退场，只留题面 + 代码）。完整界面本身也必须扁平简约，不是「先做花的再藏起来」。

**自定义（全套）：** 面板宽、停靠、折叠、重置；深浅色、密度、chrome 显隐、字号；可选强调色、题面与代码分色表面。设置用预览，不写长说明。

不得破坏：现有快捷键、relay 协议、功能行为。移动端窄屏仍可用。

## Brand Commitments

- 名：AnyView
- 用户钉死：扁平、简约、自然、大方、美观、克制；视觉优先，少文字；让人盯着题目和代码
- 克制是硬约束：不要花里胡哨，不要主题化服装（CRT、折纸、试卷纹理、霓虹）
- 无重阴影、无渐变装饰、无彩色药丸堆、无 unicode 当图标
- 默认完整工作台，Zen / 专注模式用设置或快捷键进入；完整界面本身也必须安静

## Evidence on Hand

- 真实上游协议与题库来自 AnyView / fuckView 逆向，见仓库 README
- 演示可用 `make relay-mock`；不得编造通过率、课程名、学生名单、评测基准
- 无品牌摄影、无 logo 源文件；身份靠产品名与工作台本身

## Product Principles

1. 题目和代码是唯一主角；chrome 服务它们，不解释它们。
2. 用形状、位置、状态色说话；能图标就不要句子。
3. 完整模式已经够安静；Zen 只是再减一层，不是另一套皮肤。
4. 能配的都给配，默认值必须开箱能用。
5. 计时是后台协议，不是用户要完成的任务。
